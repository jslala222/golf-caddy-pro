③ 티어 변경 경우의 수 전체 매트릭스

#상황현재 tier요청코드변경?R2 백업딜러수당처리
1 만료 후 동일 티어 재결제 (온라인) 스탠다드 스탠다드 재구독 ❌ 유지 정상 딜러ref 있으면 자동 expires_at 연장만
2 만료 후 동일 티어 재결제 (온라인) 프리미엄 프리미엄 재구독 ❌ 유지 정상 딜러ref 있으면 자동 expires_at 연장만
3 만료 후 업그레이드 (온라인) 스탠다드 → 프리미엄 ❌ 유지 경로 동일 딜러ref 있으면 자동 tier=premium + expires_at 연장
4 만료 후 다운그레이드 (온라인) 프리미엄 → 스탠다드 ❌ 유지 경로 동일 딜러ref 있으면 자동 tier=standard + expires_at 연장
5 만료 전 딜러 연장 (동일 티어) 스탠다드 스탠다드 연장 ❌ 유지 정상 자동 (크레딧 차감 기록) expires_at += days
6 만료 전 딜러가 업그레이드 연장 스탠다드 → 프리미엄 연장 ❌ 유지 경로 동일 프리미엄 크레딧 차감 tier=premium + expires_at += days
현재 구현됨 (handleExtend)
7 만료 전 딜러가 다운그레이드 연장 프리미엄 → 스탠다드 연장 ❌ 유지 경로 동일 스탠다드 크레딧 차감 tier=standard + expires_at += days
현재 구현됨 (handleExtend)
8 처음 사용자 (이용권 없음) 없음 신규 구매 신규 코드 발급 새 경로 생성 자동 정상 흐름

④ handleExtend — tier 컬럼 업데이트 필요 여부

⚠️ 현재 상태: tier DB 업데이트 누락

현재 handleExtend 코드: extendLicense({ licenseId, plan, days, dealerToken }) → DB: expires_at 만 업데이트 → tier 컬럼은 그대로!!! 예시: 김경준 스탠다드 → 딜러가 프리미엄 카드 선택 → 연장 → expires_at += 30일 ✅ → tier = 여전히 'standard' ❌ (프리미엄 크레딧 소모했는데!)

✅ 수정 필요: extendLicense에 tier 업데이트 추가

// Supabase 업데이트 시 tier도 같이 await supabase .from('aone_pro_caddypro_licenses') .update({ expires_at: newExpiresAt, tier: issueTier, ← 이거 추가 필요 plan: plan, ← 이것도 업데이트 }) .eq('id', licenseId)

⑤ 딜러 수당 자동화 — 문제점

경로딜러 연결수당 처리상태
온라인 결제 (/subscribe) URL ?ref=딜러토큰 settlements 테이블 자동 insert ✅ 자동
딜러 대시보드 크레딧 발급 issuedBy = dealer_{token} 크레딧 차감 = 이미 딜러가 선불 지급한 것 ✅ 정산 불필요
온라인 재구독 (기존 고객) ?ref 없을 가능성 높음 settlements에 dealer_id = null ⚠️ 수당 누락 가능
티어 변경 + 재구독 (온라인) ?ref 없을 가능성 settlements에 dealer_id = null ⚠️ 수당 누락 가능

💡 해결 방안 — issued_by 역추적

고객이 재구독 시 ref 없이 들어와도: 1. licenses 테이블에서 기존 코드의 issued_by 확인 issued_by = "dealer_abc123" 2. settlements 테이블에 dealer_id 자동 연결 3. 재구독 수당 자동 지급 → /api/payment/complete 에서 issued_by 체크 로직 추가 필요

⑥ 입장별 대처방안

🏢 본사

본사 입장

  • 코드 불변 원칙 유지 — 절대 신규 코드 발급으로 티어 변경 금지
  • DB tier/plan 컬럼 업데이트 권한 = 본사 관리자 + 딜러 둘 다 가능
  • 온라인 재구독 시 issued_by 역추적으로 딜러 수당 자동 처리
  • 티어 업/다운 이력 logs 테이블 기록 권장 (분쟁 방지)
🤝 딜러

딜러 입장

  • 기간연장 화면에서 현재 고객의 tier/plan 표시 → 실수 방지
  • 6개 카드 중 선택 → tier 변경 + 연장 동시 처리 가능
  • 크레딧은 선택한 tier 기준으로 소모
  • 프리미엄→스탠다드 다운그레이드도 허용 (고객 요청 시)
👤 고객

고객 입장

  • 코드 그대로 유지 — 데이터 날아가지 않음
  • 7일 전부터 상단 배너 경고 → "갱신하기" 버튼 → 결제창
  • 만료 후 전체화면 모달 → 현재 tier 파라미터 포함한 결제창 이동
  • 업그레이드/다운그레이드 선택 가능 (subscribe 페이지에서)
  • tier 변경 시 앱 재실행 후 즉시 적용 (DB→localStorage 동기화)
🖥️ 서버

서버/DB 입장

  • licenses 테이블 업데이트: tier + plan + expires_at (코드 변경 없음)
  • R2 백업 경로: 코드 기반 → 변경 없음
  • settlements: issued_by 역추적으로 딜러 자동 연결
  • tier_change_logs 테이블 추가 권장 (선택)
💾 코드(이용권)

이용권 코드 입장

  • 코드는 절대 불변 — 로컬/R2/DB 모두 동일 키로 연결됨
  • tier/plan/expires_at은 "코드의 속성"으로 언제든 변경 가능
  • 코드 자체는 스탠다드/프리미엄 구분 없음 (prefix DL- = 딜러, SM- = 온라인 등)

⑦ 구현 우선순위 로드맵

1
🔴 즉시 필요 — handleExtend tier 업데이트

딜러가 프리미엄 카드로 연장해도 DB tier가 안 바뀌는 버그. extendLicense() 또는 handleExtend 함수에서 tier 컬럼 업데이트 추가

2
🔴 즉시 필요 — 기간연장 화면에 현재 고객 tier 표시

renewResult에 tier가 있으므로 "현재: 스탠다드" 배지 표시. 딜러 실수 방지

3
🟡 중요 — subscribe 페이지 tier 파라미터 처리

LicenseGuard 갱신 링크에 &tier=기존tier 추가 → 오늘 완료 ✅

4
🟡 중요 — 온라인 재구독 시 issued_by 역추적

/api/payment/complete 에서 기존 코드의 issued_by 조회 → settlements에 dealer 자동 연결

5
🔵 권장 — 1분 주기 만료 체크 (앱 켜둔 상태)

QR 프로그램처럼 setInterval(60_000)으로 앱 켜둔 채 자정 넘어갈 때 만료 감지

6
⚪ 선택 — tier_change_logs 테이블

티어 변경 이력 기록. 분쟁 대비용. 급하지 않음
