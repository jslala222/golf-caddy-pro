🔵 안 A — 사업자 딜러 (세금계산서 구조)
안 A: 딜러가 사업자등록증 보유 (개인사업자 or 법인)
기본 개념
딜러가 사업자로서 직접 고객에게 세금계산서 or 현금영수증을 발행하고, 본사에 수수료 명목 세금계산서를 역발행하는 구조.
결제 흐름
고객
→
딜러 계좌/카드단말
→
딜러가 세금계산서 발행
→
딜러 → 본사 정산
→
본사 수수료 비용처리
세무 처리 상세
  • 고객 영수증: 딜러 명의로 현금영수증 or 세금계산서 발행
  • 딜러 → 본사 정산: 딜러가 공급한 서비스에 대해 역발행 세금계산서
  • 본사는 딜러 수수료를 매입 비용으로 처리 (부가세 공제 가능)
  • 딜러는 자신의 사업부가세 신고 의무 별도 존재 (분기별)
👍 장점
  • 세무 구조 매우 명확
  • 본사 리스크 최소화
  • 부가세 매입 공제 가능
  • 딜러가 세금 책임 직접 부담
👎 단점
  • 딜러 사업자등록 필수 → 진입장벽↑
  • 딜러별 세금계산서 교환 관리 복잡
  • 딜러가 부가세 신고 안 하면 리스크
  • 영세 딜러 확보 어려워질 수 있음
📋 안 A 실무 절차
  • 1
    딜러 사업자등록증 사본 수취
    계약 전 사업자등록 여부 확인 필수. 개인사업자/법인 모두 가능
  • 2
    딜러-본사 간 공급계약서 체결
    서비스 단가, 수수료율, 정산주기(주간/월간) 명시
  • 3
    딜러가 고객 영수증 직접 발행
    현금영수증(홈택스) or 세금계산서(전자세금계산서) — 딜러 명의
  • 4
    월 정산 시 세금계산서 교환
    딜러 → 본사 방향으로 수수료 세금계산서 발행 후 입금
  • 5
    본사 장부 매입 비용 처리
    부가세 신고 시 딜러 수수료 매입세액 공제 적용
🟢 안 B — 프리랜서 딜러 (3.3% 원천징수 구조)
안 B: 딜러 사업자 없음 → 사업소득자(프리랜서)로 분류, 3.3% 원천징수
기본 개념
딜러를 사업소득자(인적용역 제공자)로 분류. 본사가 수수료 지급 시 3.3% 원천징수 후 지급. 고객 영수증은 본사 명의로 발행.

고객

원천징수 계산 예시
# 딜러 수수료 정산 예시 (월 정산) 고객 결제금액 : 1,000,000원 딜러 수수료율 : 30% 딜러 수수료 합계: 300,000원 ────────────────────────────── 원천징수 (3.3%): -9,900원 ← 본사가 징수 후 홈택스 신고 딜러 실수령액 : 290,100원 ← 딜러 계좌 입금 ────────────────────────────── # 딜러 연소득 330만원 이하 → 종합소득세 부담 거의 없음
세무 처리 상세
  • 고객 영수증: 본사 명의로 현금영수증 or 카드전표 자동 발행
  • 딜러 수수료: 매월 3.3% 원천징수 후 지급 → 원천징수이행상황신고서 제출 (매월 10일)
  • 다음해 3월 내 사업소득 지급명세서 제출 (딜러별 인적사항 포함)
  • 딜러는 5월 종합소득세 신고 시 3.3% 기납부 세액으로 공제 적용
👍 장점
  • 딜러 사업자 불필요 → 진입장벽 최저
  • 영업직 프리랜서로 합법 운영 가능
  • 고객 영수증 본사가 일원화 관리
  • 국내 가장 보편적인 구조
👎 단점
  • 본사가 원천징수 신고 의무 부담
  • 딜러별 지급명세서 매년 제출 필요
  • 딜러가 고객 현금 직수금 시 탈세 리스크
  • 딜러 수입 많으면 종합소득세 부담 가능
📋 안 B 실무 절차
  • 1
    딜러와 프리랜서 용역계약서 체결
    수수료율, 정산주기, 원천징수 동의 조항 포함 필수
  • 2
    딜러 주민등록번호 or 사업자번호 수취
    지급명세서 제출 시 인적사항 필요. 개인정보 보관 주의
  • 3
    고객 결제 → 반드시 본사 명의로 수령
    딜러가 직접 현금 수령 후 전달 방식은 탈세 리스크. 본사 계좌/카드단말 필수
  • 4
    월 정산 시 3.3% 공제 후 지급
    지급 명세 내부 기록 유지 (딜러명, 주민번호, 수수료액, 징수세액)
  • 5
    매월 10일 — 원천징수이행상황신고서 제출
    홈택스 → 원천세 신고 → 사업소득 (A03 코드) 항목으로 신고
  • 6
    다음해 3월 — 사업소득 지급명세서 제출
    홈택스 → 지급명세서 → 개인 사업소득 제출. 미제출 시 2% 가산세
⚠️ 핵심 주의사항 — 딜러 직접 현금수령 금지 딜러가 고객에게 현금 직접 수령 후 본사에 입금하는 구조는 딜러 → 고객 간 영수증 미발행 = 탈세로 이어질 수 있음. 반드시 본사 계좌 or 본사 카드단말기로 고객 결제 받을 것.

⭐ 결론 — A · B 병행 구조 채택 권장

🔵 안 A 적용 대상
  • 기존 사업자 보유 딜러
  • 규모 있는 대리점 파트너
  • 법인 or 개인사업자 형태로 운영 중인 곳
  • 부가세 매입 공제 원하는 경우
  • 처리: 세금계산서 교환 + 본사 매입비용 처리
🟢 안 B 적용 대상 (주력 구조)
  • 사업자 없는 개인 딜러 (대부분)
  • 신규 영업직 프리랜서 딜러
  • 부업 형태 소규모 딜러
  • 처리: 3.3% 원천징수 + 본사 영수증 발행
  • 매월 원천세 신고 + 연 1회 지급명세서
💡 핵심 원칙 딜러 신규 계약 시 사업자등록 여부 확인 → A 또는 B 구조 자동 분기. 어떤 경우든 고객 결제는 본사 명의로 수령하고 영수증은 본사가 발행하는 것을 원칙으로 함. 딜러 수수료 지급 시 A는 세금계산서 수취, B는 3.3% 원천징수 후 지급.

⚠️ 세무사 확인 권장: 딜러 수가 늘어나기 전 세무사 1회 상담으로 지급명세서 누락 가산세(2%) 방지 필수.
📌 추가 참고 — 특수고용직 vs 프리랜서 차이

"특수고용직"은 근로기준법상 근로자는 아니지만 특정 고용관계(보험설계사, 학습지교사 등)에 적용되는 분류로, 딜러(영업 수수료 기반)에는 해당되지 않음.

딜러 = 사업소득자(인적용역 제공자) 분류가 정확 소득세법상 사업소득 중 인적용역(기타 자유직업소득)으로 분류 → 3.3% 원천징수 적용 (소득세 3% + 지방소득세 0.3%)
원천징수 신고 코드: A03 (사업소득 — 인적용역) 홈택스에서 원천세 신고 시 소득 구분 코드 A03 선택. 연간 지급액이 소액이라도 반드시 지급명세서 제출 의무 있음.
🚨 딜러가 시스템 밖에서 현금/계좌이체로 수금할 때 — 대처 방안
❌ 핵심 문제

딜러가 우리 시스템(포트원) 외부에서 고객에게 현금 or 타인 계좌로 수금하면
→ 포트원 webhook이 실행되지 않음 → 서버에 아무것도 안 들어옴 → 영수증 발행 구조 무력화
→ 딜러가 사업자임에도 고객에게 세금계산서/현금영수증 미발행 시 탈세 리스크 발생

🛡️ 방법 1 — 딜러 계약서에 책임 명시 (즉시 가능)
딜러가 고객에게 현금 수령하는 행위 자체는 기술적으로 막을 수 없음.
계약서에 아래 조항 삽입 → 본사 면책:
# 딜러 계약서 필수 삽입 조항 조항: 딜러가 고객으로부터 직접 현금 or 계좌이체로 수금 시, 고객에 대한 세금계산서/현금영수증 발급 의무는 전적으로 딜러에게 있음. 이로 인한 세무·법적 책임에 대해 본사는 면책.
👍 장점
  • 즉시 적용 가능
  • 추가 개발 없음
  • 본사 법적 보호
👎 단점
  • 딜러가 지키지 않으면 통제 불가
  • 사후 대응만 가능
⭐ 방법 2 — 딜러 토큰 선충전 구조 (근본적 해결)
딜러가 고객에게 코드를 발급하려면 반드시 본사에 먼저 충전해야 하는 구조.
딜러가 고객에게 얼마를 받든 우리는 이미 딜러에게서 결제 완료 → 세무 처리 완료.
딜러가 본사에 선결제 충전
→
이 시점에 영수증 처리 완료 ✅
→
딜러가 토큰으로 고객 코드 발급
→
고객-딜러 간 결제는 딜러 책임
# 핵심 원칙 본사 입장: 딜러에게 선충전 받을 때 영수증 처리 완료 딜러 입장: 고객에게 얼마 받든 자유 (단, 딜러 사업자면 세금계산서 발행 의무) 리스크 : 본사 → 0 / 딜러 → 딜러가 직접 부담
현재 기획된 딜러 토큰 충전 기능 = 이 구조의 핵심 딜러 코드 발급 경로를 토큰 충전 → 발급으로 일원화하면 완전 해결. 참고: 기획_딜러_수수료_토큰.html
👍 장점
  • 근본적 구조 해결
  • 본사 세무 리스크 0
  • 딜러 수금 방식 자유
👎 단점
  • 딜러 토큰 충전 시스템 구현 필요
  • 딜러 선충전 부담 발생 가능
🔒 방법 3 — 이용권 코드 발급 채널 통제
딜러가 고객 코드를 발급받으려면 반드시 우리 딜러 포털(시스템)을 통해야 함.
코드 자체는 본사가 쥐고 있으므로, 발급 기록이 DB에 모두 남음 → 추적 가능.
현재 이미 적용되어 있는 구조 딜러 대시보드에서만 코드 발급 가능. 단, 딜러가 코드 발급 후 고객에게 현금 수령하는 것은 막을 수 없음.
방법 공수 효과 본사 리스크
계약서 명시 즉시 본사 면책 없음
딜러 선충전 구조 ⭐ 중간 근본 해결 없음
코드 발급 채널 통제 낮음 추적 가능 낮음
⭐ 최종 권장: 방법 1 + 방법 2 병행 계약서로 즉시 본사를 법적으로 보호하고, 딜러 토큰 선충전 구조를 완성하면 구조적으로도 완전 해결됨. 방법 3은 현재 이미 적용 중.
